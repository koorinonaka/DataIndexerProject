    リネームしても、参照は壊れない。

    DataIndexer は UE5 のためのゲームデータ管理プラグイン。すべての行は GUID（FDataIndexerPrimaryKey）で識別されるため、リネームしても既存の参照はすべて有効のまま。型安全な C++ / Blueprint API と Schema による一元管理が、データ規模が拡大しても保守コストを抑えます。

    1. GUID ベースの PrimaryKeyキー名を変更しても参照はそのまま維持。Blueprint やコードの参照が壊れません。
    2. Key 参照の追跡Key がどのアセット・コードから参照されているかをエディタ上で確認できます。
    3. 継承時の上書き子 Repository 内で特定の Row だけを上書き。UCompositeDataTable にはなかった機能で、変更箇所が明確に追えます。
    4. セカンダリクエリBlueprint・C++ どちらからも、定義したインデックス経由で O(1) に近い効率で Row を検索。行数が増えても性能が劣化しません。

    キーは行を作ったときに一度だけ生成され、変わらない。表示名を変えても参照には影響しない。

    スプレッドシート感覚の編集から、型安全な管理まで。

    エディタガイド →
    editor-guide/data-view 編集はセルで。整合性はスキーマで。 セル単位の選択、Shift / Ctrl による拡張選択、矩形範囲のドラッグ、ダブルクリックでインライン編集。
    concepts/keys-and-handles リネームしても、参照は壊れない。 エディタ上で Key 参照を可視化。アセット・コード横断で追跡でき、安心してリファクタリングできる設計。
    how-to/parent-hierarchy 継承と統合で、データを重ねる。 親 Repository の合成で実現。子 Repository から特定の Row だけを上書きでき、変更箇所が明確に追える。
    concepts/indexes 属性による、高速な逆引き。 スキーマで定義した Index 経由で O(1) 近似の高速検索。

    C++ でも Blueprint でも、同じデータに同じ整合性で。

    API リファレンス → 
    USTRUCT(BlueprintType)
struct FItemRow
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadWrite) FText       DisplayName;
    UPROPERTY(EditAnywhere, BlueprintReadWrite) EItemType   Type;
    UPROPERTY(EditAnywhere, BlueprintReadWrite) EItemRarity Rarity;
    UPROPERTY(EditAnywhere, BlueprintReadWrite) int32       BaseValue = 0;
};
using FItemInterface = DataIndexer::TNativeSchemaInterface<FItemRow>;

if (const FItemRow* Row = FItemInterface::FindRow(Repository, PrimaryKey))
{
    FText Name = Row->DisplayName;
}

FItemRow Filter; Filter.Rarity = EItemRarity::Rare;
for (const FDataIndexerPrimaryKey& K :
     FItemInterface::GetPrimaryKeys(
         Repository, UItemSchema::ByRarityIndex(), Filter))
{
    Process(*FItemInterface::FindRow(Repository, K));
}
    型はスキーマで一元管理
    C++ は TNativeSchemaInterface<T> で型安全なクエリ。Blueprint は Get Row ノードで同じ行データを視覚的に扱えます。
    保存・Cook 時に自動検証
    Row 間のリレーションと参照整合性をスキーマが自動チェック。データ不整合をランタイム前に検出します。
    O(1) 近似の逆引き
    スキーマで Index を宣言すれば、属性ベースの検索が高速に。行数が増えても性能劣化なし。

    既存の DataTable プロジェクトからは 「DataTable から移行する」 ガイドで段階的に移行できます。
